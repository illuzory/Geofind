# Интеграция OSRM после открытия сети

Это отчёт предыдущего этапа. Текущая проверка адресов, согласований и импорта: [ADDRESS_RELEASE_VALIDATION.md](ADDRESS_RELEASE_VALIDATION.md).

27 октября 2026 года успешно проверен HTTPS-доступ к `router.project-osrm.org`. Подключён публичный автомобильный demo OSRM. Локальный сервер на порту 5000 отсутствует; клиент использует удалённый endpoint.

Это проверка дорожного движка на условных координатах MVP, не подтверждение адресов оборудования или фактических времен поездок. Пробки не учитываются. Сервер не сообщает версию графа; результаты сгруппированы идентификатором наблюдения `public-osrm-observed-2026-10-27T06:34:06.150955+00:00`, а не приписанной ему версией данных. Наблюдение и последующий повтор из кэша различаются.

## Найденная и исправленная проблема

Table с параметром `radiuses=3000;...` возвращал HTTP 400 NoSegment для всего пакета, если хотя бы один узел сетки был дальше 3 км от дороги. Повтор диагностического запроса без радиусов подтвердил гипотезу: 50 результатов, из них 44 в пределах 3 км, максимальное расстояние привязки 7061.93 м.

Теперь Table возвращает привязки всех узлов; клиент проверяет `sources[].distance` и `destinations[].distance` индивидуально. За пределами 3 км время не принимается, состояние — `off_network`. Порог не увеличен. Отсутствующая или невалидная метаинформация о привязке останавливает расчёт. Route выбранной площадки по-прежнему запрашивается со строгим радиусом 3 км. Ключ кэша изменён, чтобы старые результаты не обходили новую проверку.

Сетевая ошибка, неверная матрица и отсутствие пути остаются разными ситуациями. Географические точки не передвигаются вручную, чтобы получить «хорошее» время.

## Браузер и ресурсы

Реальный Chromium, приложение с настроенным OSRM, внешние запросы браузера отключены (серверный доступ OSRM разрешён):

- Кнопка расчёта строит базовую карту, выбранный маршрут и показатели 3/4.
- Дополнительные инженеры в Нижнем Тагиле меняют покрытие на 4/4.
- Загрузка изменённого Excel обновляет устройства 54 → 55; CSV имеет `calculation_mode=osrm` и актуальные значения.
- Leaflet canvas, маркеры и всплывающая карточка работают, ошибок JavaScript нет.
- Отдельно повторён автономный сценарий, он также проходит.

Первый сетевой прогон полной проверки: 30.326 с, пиковая RSS клиента 186.1 МиБ при лимите адресного пространства 16 ГиБ. Повтор из SQLite-кэша — менее секунды. Память удалённого OSRM не измерялась: эти числа не характеризуют локальную подготовку или хранение дорожного графа.

## Воспроизведение и использование

```bash
export OSRM_URL=https://router.project-osrm.org
export OSRM_CACHE_NAMESPACE=public-demo-$(date -u +%Y%m%dT%H%M%SZ)
./scripts/start.sh
# В другом терминале:
.venv/bin/python scripts/validate_osrm.py --namespace "$OSRM_CACHE_NAMESPACE"
.venv/bin/python scripts/browser_smoke.py --mode osrm
```

`validate_osrm.py` создаёт JSON-отчёт, CSV и автономные HTML-карты в `artifacts/osrm/`; сетевые проверки не выполняются в обычных pytest/CI. Книгу с исходными пользовательскими строками можно передать через `--workbook data/equipment_inventory_mvp.xlsx`.

Согласно [официальной политике](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server), публичный demo ограничен разумными некоммерческими сценариями и максимумом 1 запрос/с, без гарантий доступности и обновления графа. Клиент сериализует начало запросов публичному серверу с интервалом не менее 1.05 с, без автоматических сетевых повторов; UI ограничивает публичный расчёт 1000 ячейками и тремя сервисами. Для регулярной нагрузки нужен свой OSRM и настоящая версия графа в `OSRM_DATA_VERSION`.
