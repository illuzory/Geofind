# Geofind · Урал

MVP интерактивного анализа доезда выездного сервиса по Свердловской области. Стартовая условная точка инженеров — Екатеринбург, ул. Буторина, 6. Адрес не геокодирован: координаты выбраны для демонстрации.

Карта показывает площадки, инженеров, зоны доезда и выбранный маршрут. Можно добавить инженеров в других городах, менять скорость модели, подготовку к выезду и пороги SLA, загрузить обновлённую книгу Excel, изучить оборудование и выгрузить результаты.

## Быстрый запуск

Python 3.12, Linux. Из корня checkout:

```bash
./scripts/setup.sh
./scripts/start.sh
```

Сервер использует порт 8501; другой порт задаётся переменной `PORT`. Во внешней среде используйте её механизм открытия порта. В облачной задаче используется существующий checkout — дополнительный Git worktree не нужен. Процессы после восстановления среды запускаются заново.

Для Windows: создайте `.venv` через `python -m venv .venv`, установите `requirements.lock`, затем запустите `python -m streamlit run app.py` активированным интерпретатором. Windows отдельно не проверялся.

## Данные и обновление

В репозитории `data/demo_inventory.xlsx` — полностью синтетическая книга: 272 устройства, 16 городов; распределение по городам соответствует исходному примеру с добавлением трёх городов. В пилоте участвуют Екатеринбург, Нижний Тагил, Каменск-Уральский и Серов: 54 устройства, 4 площадки.

Адаптированная пользовательская книга `data/equipment_inventory_mvp.xlsx`, если присутствует, имеет приоритет. В ней сохранены все 254 исходные записи и добавлены 18 демонстрационных устройств, по 6 в трёх новых городах. Эта книга исключена из Git; исходный загруженный файл не изменяется. За пределами пилота остальные города остаются в книге и доступны в таблице оборудования, но не участвуют в расчёте.

Листы:

| Лист | Поля |
|---|---|
| Equipment | Site Name, Device Name, Device Type, Serial Number, Status, Vendor, необязательный Data Source |
| Sites | site_id, name, latitude, longitude, region, address, is_demo |
| Services | те же поля координат; каждая строка — точка выезда |
| Readme | пояснения, не участвует в импорте |

Имена `Sites.name` уникальны и связываются с `Equipment.Site Name`. Серийные номера и пара «площадка + имя устройства» уникальны. `site_id` не должен меняться при переименовании площадки; ID сервисов отличаются от ID клиентов. Координаты региональных площадок проверяются по границе области. Сервис может находиться в соседнем регионе, если его покрывает выбранный граф.

Скачайте книгу в интерфейсе, измените строки и загрузите её через «Обновить таблицы» → «Применить таблицу». Некорректная книга не заменит предыдущую. Обновления действуют в текущей сессии; для постоянного стартового набора сохраните книгу в `data/equipment_inventory_mvp.xlsx` на машине приложения. Загрузка в браузере не записывает файл в Git и не меняет данные других сессий.

Восстановить адаптированную книгу из оригинала:

```bash
.venv/bin/python scripts/prepare_data.py --source /path/to/equipment_inventory.xlsx --output data/equipment_inventory_mvp.xlsx
```

Все координаты текущего примера условные. Оборудование исходной таблицы не считается физически расположенным в указанных городских центрах.

## Два явных режима расчёта

**Демо · дорожная модель** работает автономно. Включены обобщённые дороги Natural Earth 1:10m и граница области. Кратчайший по времени путь ищется по этому графу алгоритмом Дейкстры. Дороги двусторонние, пересечения плоские, скорость единая и меняется в интерфейсе. Подъезды к обобщённой дороге — модельные прямые отрезки при 20 км/ч, не более 25 км. Время не является подтверждённой оценкой реального автомобильного маршрута.

Пример при 65 км/ч, без подготовки, только Екатеринбург:

| Площадка | Модельное время | При порогах 4/6/8 ч |
|---|---|---|
| Екатеринбург | 0 ч 06 мин | В SLA |
| Нижний Тагил | 2 ч 08 мин | В SLA |
| Каменск-Уральский | 1 ч 34 мин | В SLA |
| Серов | 5 ч 28 мин | Риск |

Добавьте инженеров в Серове: площадок в SLA станет 4 из 4. Нулевое время означает совпадающие условные координаты сервиса и клиента; подготовка добавляется отдельно.

**OSRM · автомобильный маршрут** подключается к отдельному маршрутизатору с подготовленным OSM-графом нужного покрытия:

```bash
export OSRM_URL=http://127.0.0.1:5000
export OSRM_DATA_VERSION=ural-car-<date-and-profile-version>
./scripts/start.sh
```

Для удалённого сервера требуется HTTPS. Подготовьте граф области с соседними дорогами: оптимальный путь может выходить за границу. Изменяйте `OSRM_DATA_VERSION` при замене данных или профиля; это часть ключа SQLite-кэша. Старые версии можно удалить вместе с `.cache/osrm.sqlite` при остановленном приложении. Для OSRM MLD требуется сервер с `--algorithm mld`; подготовка PBF выполняется отдельно. Установка OSRM/подготовка большого графа не входят в уже проверенный автономный запуск.

В OSRM-режиме нажмите «Рассчитать дорожный сценарий». Запросы идут от инженеров к площадкам/общим узлам, пакетами до 50 назначений. Привязка к дороге ограничена 3 км. `null` маршрута отличается от отказа API: отказ останавливает расчёт. Ошибки не кэшируются как отсутствие пути. Геометрия запрашивается только для выбранной площадки. Текущие пробки не учитываются.

После предоставления сетевого доступа проверена интеграция с `https://router.project-osrm.org`: Table и Route совпали для четырёх площадок; рассчитана сетка 568 ячеек и сценарий с инженерами в Нижнем Тагиле. Реальные координаты по-прежнему не подтверждены, пробки не учитываются. См. [docs/OSRM_VALIDATION.md](docs/OSRM_VALIDATION.md).

Для подключения публичного demo в MVP:

```bash
export OSRM_URL=https://router.project-osrm.org
export OSRM_CACHE_NAMESPACE=public-demo-$(date -u +%Y%m%dT%H%M%SZ)
./scripts/start.sh
```

В интерфейсе нажмите «Рассчитать дорожный сценарий». При заданном подключении OSRM выбран по умолчанию; запросы не запускаются до нажатия кнопки. Автономный режим остаётся доступен отдельно.

Публичный demo не сообщает версию графа: `OSRM_CACHE_NAMESPACE` — идентификатор наблюдения и кэша, а не выдуманная версия OSM. Для обновления наблюдения измените этот идентификатор и перезапустите приложение; при использовании своего сервера задайте настоящую `OSRM_DATA_VERSION`. Публичный demo предназначен для разумных некоммерческих проверок, без гарантий доступности/обновления данных. Запросы ограничены одним в секунду, до 1000 ячеек и трёх сервисов; для большей нагрузки нужен свой OSRM. [Официальные условия demo](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server).

Привязка проверяется по расстояниям, возвращённым Table: узлы дальше 3 км от дороги не получают время. Это сохраняет ограничение привязки и позволяет одной далёкой точке не обрывать весь пакет. Время OSRM относится к привязанным дорожным точкам; подход от фактической координаты отдельно не добавляется.

## Алгоритм покрытия и ограничения

- Общая сетка EPSG:32641, шаг 10/20/40 км; ячейки обрезаются границей области.
- До одной и той же точки считаются времена всех активных сервисов. Победитель — минимальное время, при равенстве — меньший `site_id`.
- Реальные площадки считаются отдельно, а не получают время от центра ячейки.
- Время до прибытия = время пути + подготовка. Пороги по умолчанию: ≤4, (4;6], (6;8], >8 часов.
- Соседние ячейки одного сервиса и класса объединяются. Пересечения не отдаются большему полигону; выпуклые оболочки не используются; MultiPolygon сохраняются.
- Зоны — аппроксимация по представительной точке ячейки. Победитель внутри ячейки может меняться. Серая область означает отсутствие расчёта в выбранном графе, а не установленное отсутствие реальной дороги.
- Нет моделирования ремонта, расписаний и загрузки инженеров, погоды, пробок, запасов запчастей. Active/Standby оборудования — фильтр инвентаризации, не доступность инженеров.
- Ограничения MVP: один регион, до 10 сервисов, 2000 площадок, 10000 ячеек, 50000 строк в листе, XLSX до 10 МБ/50 МБ после распаковки.
- Кэш матриц OSRM — на диске; в RAM хранится ограниченное число деревьев кратчайших путей и результатов сценариев. Генератор не загружает дорожный граф всей России.

## Проверка и экспорт

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/benchmark.py
.venv/bin/python scripts/export_demo.py --workbook data/demo_inventory.xlsx --output artifacts
# При запущенном приложении и установленном Chromium:
.venv/bin/python scripts/browser_smoke.py --chromium /usr/bin/chromium
# Для запущенного приложения с подключённым OSRM:
.venv/bin/python scripts/browser_smoke.py --mode osrm
# Явная сетевая интеграционная проверка (не входит в pytest/CI):
.venv/bin/python scripts/validate_osrm.py --step 20
```

Экспортируемый HTML — автономный снимок карты со слоями и всплывающими карточками. Пересчёт сценариев и импорт данных доступны в Streamlit-приложении. Экспорт CSV содержит секунды доезда/прибытия, выбранный сервис и режим расчёта.

Сводка проверок — [docs/VALIDATION.md](docs/VALIDATION.md). Аудит исходного прототипа — [docs/AUDIT.md](docs/AUDIT.md). Происхождение данных и лицензии — [docs/SOURCES.md](docs/SOURCES.md).

Проект подготовлен в отдельной ветке; публикация на GitHub и развёртывание выполняются отдельно. Пользовательская книга, кэш и артефакты исключены из Git. NetBox, почта и заявки не добавлены.
